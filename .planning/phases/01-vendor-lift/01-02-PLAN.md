    every test below so no single test re-implements file discovery:

    - `REPO` — the repository root, resolved as the parent of the `tests` directory, never from
      the current working directory.
    - `tracked_files()` — the output of `git ls-files` run with `cwd=REPO`, returned as paths
      relative to `REPO`. Use the git index rather than a filesystem walk so untracked scratch
      files and `__pycache__` can never influence a result.
    - `text_files()` — `tracked_files()` filtered to suffixes `.py`, `.xml`, `.po`, `.md`, `.ini`,
      `.txt` and extensionless files, read as UTF-8 with `errors='replace'`. Binary assets are
      excluded by suffix, not by sniffing.
    - `source_scan(pattern, extra_excludes=())` — iterate `text_files()`, skip any path whose
      first component is `.planning` or `tests`, skip `VENDORED.md`, `CREDITS.md`, `COVERAGE.md`
      and `README.md`, and return a list of `(path, lineno, line)` tuples for every regex match.
      Those four documents are excluded because they are required to name the upstream module and
      the original add-on id by name; forgetting that exclusion produces a gate that can never go
      green. Every test that reports a failure must report path and line number, never a bare
      count, because a bare count cannot be acted on.

    a shadowing bug waiting for a machine with a sibling add-on installed.

    import and continue. For everything else, take the first dotted component of the module name
    and assert it is a member of `sys.stdlib_module_names`, or begins with `xbmc`, or equals
    `resources`. Report the offending module name together with the file and line. Guard against
    a vacuous pass by asserting at least 20 import statements were visited.

    `test_tree_compiles` — call `compileall.compile_dir` on `REPO/'resources'` with `quiet=2`,
    `force=True` and `legacy=False`, and `compileall.compile_file` on `entrypoint.py` and
    `service.py`. Assert every return value is truthy. This is the only check in the file that
    catches a regex rewrite which ate a character: such a file greps clean and fails at import.

    `test_no_eval` — assert the two patterns for dynamic code execution (word-boundary `eval`
    followed by optional whitespace and an open parenthesis, and the same for `exec`) find zero
    matches across tracked `.py` files. The `tests` directory is already excluded by
    `source_scan`, which is what lets this gate file name the constructs it forbids. Note that
    `re.compile` is not a false positive for these two patterns because both are word-anchored on
    the function name itself.

    changes list of the shape `export.py` writes; and an item dict of the shape the OneDrive
    provider's extraction produces, containing `str`, `int`, `float`, `bool`, `dict` and `list`
    values with `last_modified_date` as a string. Assert each survives two consecutive
    `json.dumps` then `json.loads` round trips unchanged, so the conversion is idempotent and not
    merely lossless once. Then assert explicitly that a tuple does not survive the round trip and
    that a dict with a non-string key does not either — these are the two shapes the research
    identified as not surviving the serializer swap, and asserting them documents that the write
    sites were checked rather than assumed.

    `test_all_http_calls_have_timeout` — parse every tracked `.py` file under `resources/` with

    `ast.Attribute.attr`, to `urlopen` or `urlretrieve`. For each, assert a keyword named
    `timeout` is present. Do not include `Request` in the callee set — a `Request` object carries
    no timeout and adding it would create a false requirement. Guard against a vacuous pass by
    asserting at least one such call was found; a sweep that passes because it found nothing is
    the failure mode this test exists to prevent.

    `test_tree_compiles` is expected to be red until its owning plan lands. That is by design.
