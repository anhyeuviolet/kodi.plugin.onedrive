<objective>
Cut the last three cords. Resolve the eight hardcoded lookups that still name the upstream module
by id, vendor the QR encoder the sign-in dialog needs, replace the one date-parsing call that
needs an external module, and delete the external import from the manifest — so `addon.xml`
declares exactly one dependency and the add-on carries everything it runs on.

Purpose: these are the changes that look correct on the maintainer's machine and fail for users.
Every one of the eight id lookups keeps resolving as long as any sibling cloud-drive add-on is
installed, which is why they belong in one commit that the clean-profile pass validates as a unit.
Closing them is also what makes the merged skin tree live: all three dialog construction sites
resolve their skin path through the common-addon path accessor, so setting the common-addon id to
None redirects all three to this add-on's own path with no edit to any construction site.

Output: a tree with no add-on-id literal for the upstream module, a vendored QR encoder with both
its licences, a standard-library date parse, and a manifest with one import.
</objective>

    of returning `None` on failure. Kodi bundles CPython 3.11.2 on Nexus, 3.11.7 on Omega and
    3.14.6 on the master line, and the standard-library parser gained general ISO-8601 support

    relying on the surrounding exception handler. The parser accepts only three or six fractional

    Note in the SUMMARY that the seven-digit case was not observed directly and is carried from
    research as an assumption — the truncation is harmless if it never occurs.

    block in `addon.xml`, leaving exactly one import: `xbmc.python` at version `3.0.1`, which plan
