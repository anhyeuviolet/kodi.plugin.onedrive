<objective>
Take ownership of the module. Copy `script.module.clouddrive.common` v1.4.0 verbatim from the
`matrix` branch at a pinned commit, rename it under this add-on's own namespace, and merge its
skin and language resources into this add-on's — so that every Python import in the tree resolves
inside this add-on's directory and nothing can be shadowed by a sibling add-on's copy.

Purpose: this is the phase's end-to-end proof. Until this lands, the architecture is a hypothesis;
after it lands, the vendoring mechanism is demonstrated across every layer the phase touches — the
copied tree, the rewritten imports, this repository's own four import sites, the merged resources,
and the compile check that proves none of it was mangled. Everything after this plan is expansion
from a proven slice.

The add-on remains fully runnable at every commit boundary here. The external module import stays
declared in `addon.xml` until plan 01-05, so on a clean install Kodi still resolves the eight
hardcoded module-id lookups and the module still supplies `pyqrcode` and `dateutil`. Nothing about
the running behaviour changes in this plan; only where the code lives changes.

Output: `resources/lib/vendor/clouddrive_common/`, the merged skin tree, and two `.po` files
holding both id blocks side by side.
</objective>
