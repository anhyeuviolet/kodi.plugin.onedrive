<objective>
Make the dialog the phase's actual product: a code big enough to read across a room, a countdown that
ticks, a way to get a fresh code when the old one dies, and a cancel that leaves nothing behind.

Purpose: the project's stated core value is signing in from a sofa with a remote. Everything else in
this phase is machinery in service of this one screen. It arrives carrying three defects — a font
name the stock skin does not define so the body text has always rendered smaller than intended, a
focus call inside the per-tick update that makes the required focused expiry action impossible, and a
destructor that deletes an unset path when the dialog is abandoned before it initialises.

The layout also has to invert. It was built around a pattern image occupying the left third with the
text as a body block, which is the right shape when the image can carry a complete sign-in address.
It cannot: the provider does not return the field that would allow that, measured in all three spike
runs. So the code is the element, and the image is a convenience.

This plan keeps the existing construction and update signatures working. The flow that drives the new
behaviour lands in plan 03-08; keeping the old callers compiling means the commit boundary here is
still a running add-on.

Output: a layout and a dialog class ready for a two-clock poll loop to drive.
</objective>
