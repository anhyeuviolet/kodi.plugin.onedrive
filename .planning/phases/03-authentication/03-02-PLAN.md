<task type="auto">
  <name>Task 1: The build, drawn from the git index</name>
  <read_first>
    - `addon.xml` lines 1-10 — the id and version the archive's directory name and filename must agree with
    - `tests/test_vendor_gates.py` lines 88-105, the `tracked_files` helper — the same reason applies here and the same mechanism should be used: the index, null-separated, so a path with a space or a non-ASCII character is read verbatim
    - `.gitignore` — what is already excluded from the index, and therefore what the build gets for free
  </read_first>
  <files>tools/build_addon_zip.py</files>
  <action>
    Write the build as an importable module with a function taking an output directory and returning
    the path it wrote, plus a small command-line entry point. A test has to be able to drive it into
    a temporary directory; a script that only works as a subprocess against the repository root
    cannot be tested without leaving an archive in the tree.

    Read the id and the version from the manifest with the XML parser rather than a regular
    expression, and derive both the archive's single top-level directory name and its filename from
    them.

    **Record this correction in the commit body.** The requirement text names a top-level directory
    `plugin.onedrive/`, which was written before this add-on took its own id. Kodi resolves an
    installed add-on by matching the archive's top-level directory against the id in the manifest
    inside it; a mismatch is refused at install. The directory must therefore be named for the
    current id and the requirement is corrected in place rather than implemented literally — the
    same treatment the drive-enumeration requirement received when a measurement contradicted it.

    Source the member list from the git index, filtered to what actually ships. Exclude the first
    path component for the planning record, the test suite and this tool directory; those are
    development artefacts and one of them contains live measurement output. Do not hand-maintain an
    include list — an exclusion list over the index fails safe when a new source directory is added,
    where an include list would silently drop it.

    Write members with an explicit archive name of the directory name joined to the relative path,
    using forward separators regardless of host, and sort the member list so two builds from the
    same index agree. Use deflate compression.
  </action>
  <verify>
    <automated>python -c "import subprocess,sys,tempfile,pathlib; d=tempfile.mkdtemp(); r=subprocess.run([sys.executable,'tools/build_addon_zip.py','--out-dir',d]); sys.exit('build failed rc=%d' % r.returncode) if r.returncode else None; z=list(pathlib.Path(d).glob('*.zip')); sys.exit('no archive produced in %s' % d) if not z else print('built', z[0].name)"</automated>
