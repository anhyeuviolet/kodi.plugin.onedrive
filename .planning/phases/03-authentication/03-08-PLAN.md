<objective>
Replace the third party in the middle of sign-in with a direct conversation with the identity
provider, and make the dialog built in plan 03-06 actually drive it.

Purpose: this is the reason the project exists. The current flow asks a hosted server to broker the
exchange, tells it the user's address before anything else happens, and hands it the tokens. That
server was measured alive, not dead — so this plan removes a working third-party dependency, and
every commit in it has to leave a running add-on.

Three things land together because they cannot land apart. The provider methods, the account
resolution and the sign-in flow are one seam: rename the methods without rewriting the flow and
sign-in breaks; rewrite the flow without fixing the account resolution and the first call after
acquiring a token fails with a permission the locked scope set does not grant. So this is the
phase's heaviest plan, deliberately, because splitting it would buy smaller commits at the cost of a
broken one.

Output: sign-in that works against this project's own registration, with nothing in the middle.
</objective>
