<objective>
Turn the provider's failure vocabulary into sentences a person can act on from a sofa, and put every
word this phase will show on screen into the catalogue before any plan needs it.

Purpose: a business tenant can refuse this application for reasons the add-on cannot fix, and those
refusals arrive as a generic error with the real cause buried in a paragraph nobody parses. Rendered
as "sign-in failed, please try again", the user retries forever. The escape hatch this project ships
— a custom application identifier at expert level — is worthless unless the message that needs it
says so.

The copy lives here rather than scattered across the plans that use it because the catalogue's
partition gate asserts the identifier set exactly, so every addition has to move the gate's expected
set in the same commit. Doing that once is one edit; doing it in four plans is four chances to leave
the gate red.

Output: the failure table with its tests, and the phase's whole English catalogue.
</objective>
