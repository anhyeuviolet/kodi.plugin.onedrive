<objective>
Make the root list the account list the requirement describes, close the two security holes the
research found in this file, and take out the last of the third party.

Purpose: three concerns share one file and one another's edges, so they share a plan. The account
list needs a re-authorise option and a way to show an account whose credentials went stale — which
is the channel by which the background service's silent failure reaches a user, without the service
ever opening a dialog. The router needs an explicit mapping, because it currently calls whatever
method a plugin address names, and adding the re-authorise action touches that code anyway. And the
failure handler needs to stop writing raw response bodies to the log and start rendering the sentences
plan 03-05 wrote — while also losing the two branches built around the third party and the reporter
whose only address source disappears with them.

Output: a root list a person can operate with a remote, a router that cannot be told to call
something arbitrary, and a log that does not contain credentials.
</objective>
